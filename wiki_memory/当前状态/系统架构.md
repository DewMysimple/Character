# 系统架构

## 架构概览

页面采用 React 控制壳加原生 Canvas 场景引擎。React 管理播放状态、参数和面板显示；Canvas 在单个动画循环中绘制代码卡片、文字粒子、蝴蝶线稿和花朵线稿。

## 模块关系

| 模块 | 职责 | 依赖 | 入口 |
| --- | --- | --- | --- |
| `App.tsx` | 保存控制参数，连接引擎快照和面板 | React、SceneEngine | `src/main.tsx` |
| `AnimationCanvas.tsx` | 创建高 DPI Canvas、ResizeObserver、Pointer Events 和动画生命周期 | React、SceneEngine | `App.tsx` |
| `ControlPanel.tsx` | 播放、重播、时间轴、分组参数、蝴蝶轨道实验台、指针扰动实验台和恢复默认 | React | `App.tsx` |
| `scene.ts` | 场景状态机、局部传播与按列分组的坍塌调度、半隐式 Euler 更新和 Canvas 绘制 | Canvas API、类型定义 | `AnimationCanvas.tsx` |
| `types.ts` | Stage、PhysicsConfig、粒子和场景快照类型 | 无 | `scene.ts` |

## 数据流

用户操作先更新 React 参数。连续数值通过 ref 同步到 Canvas 引擎，避免每帧重新渲染 React 树。Canvas 指针事件将屏幕坐标转换为 720×960 设计坐标后直接调用 `SceneEngine.setPointer`，不经过 React state。引擎根据时间、指针和参数更新对象，并以低频快照更新面板上的阶段、进度和数量。

## 场景阶段

- `intro`：0.0 至约 1.12 秒，显示代码卡片和植物轮廓。
- `falling`：从约 1.12 秒开始，默认使用约 3.2 秒的局部传播窗口；缺口先保持在中心，再向周围扩散。局部扩散模式以空间距离保持局部失稳方向，再为每个字符叠加独立的确定性释放排序扰动、初始横向速度和旋转相位，同一传播波内不会锁成三字一组或规律横排；同列坍方会把中心连续列作为完整缺口单元，中心几列在短窗口内依次打开，外侧每列按距离连续泄露，不抽样释放列内零件。
- `morphing`：字符掉落到 650 至 776 的花丛高度后才淡出并生成蝴蝶；阶段结束时间根据坍塌传播时长动态计算，避免传播尚未完成就提前切换叙事阶段。
- `bloom`：动态坍塌和变形阶段结束后至 8.0 秒，花茎、叶片和花瓣依次生长。

8 秒后时间轴保持在完成状态，蝴蝶使用不受时间轴上限影响的 `motionTime` 持续盘旋。

蝴蝶的飞行相位与扇翅相位分离，扇翅频率由 `PhysicsConfig.wingBeatFrequency` 控制，默认 2.8Hz，低于原先写死的快速频率。当前只保留围绕花朵飞行：每只蝴蝶使用自己的 `flowerX`、`flowerY` 作为轨道中心，`butterflyOrbitRadius` 和 `butterflyOrbitHeight` 分别控制水平和垂直半径，`butterflyOrbitSpeed` 控制轨道角速度，`butterflyOrbitTilt` 控制椭圆倾角，`butterflyOrbitWobble` 控制半径的周期呼吸，`butterflyOrbitDrift` 控制花头周围的低频漂移，`butterflyFlowerAttraction` 控制跟随花头的转向强度。飞行速度、大小和扇翅频率仍可独立调节。目标点固定绑定花头并保持在安全区域内，配置变化只影响已有蝴蝶的后续运动，不重建粒子、不重播；控制台“恢复默认”替换全部 React 参数，不强制重播。

花朵使用 `flowerWindStrength` 和固定随机相位产生低频自然风动；指针以花头为中心，在 `flowerPointerRadius` 内按 `pointerFalloff` 计算左右偏移，并由响应速度和回归速度控制无跳变的跟随。花朵姿态由同一条二次曲线统一计算：根部坐标固定，指针偏移同时影响枝条控制点和花头终点，花头主体绘制在枝条终点，叶片从实际枝条曲线取点，因此整株连续移动而不会出现“尸首分离”。蝴蝶在 `butterflyPointerRadius` 内使用 `butterflyPointerRepulsion` 施加二维远离力，指针离开后由 `butterflyPointerReturn` 加速回到原花朵轨道。指针参数在完成态仍实时生效，指针状态不改变花朵绑定或时间轴。花枝不再由独立 `StemSeed` 额外绘制，统一由 `Flower` 对象承担，避免完成态出现无花空根。

`PhysicsConfig.collapseMode` 和 `collapseDuration` 控制文字变化形式与传播观察时长，默认是 `local-collapse` 和 3.2 秒；局部模式使用每个字符独立的确定性释放微偏移，字符被波及后从源位置进入接近零初速的单向重力下坠，不追踪中心目标，也不设置中间汇聚阶段。下落积分在长帧时拆为安全子步，避免卡顿造成位置跳跃。`column-collapse` 使用中心 5 列作为初始缺口窗口，随后以单列为传播单位按中心到外围连续释放；同一列字符共享释放时刻和列级速度，源字符选择仍优先保留完整列，未进入动态列范围的字符保持为卡片中的静态文字，避免形成半列断裂或四列一批的僵硬节奏。

静态纸张背景在引擎内缓存，粒子扰动相位在生成时预计算，避免每一帧重复生成纹理和随机值。

## 运行与部署

开发环境使用 Vite，默认端口为 5173；若端口占用，Vite 会选择下一个可用端口。生产构建由 `tsc -b && vite build` 完成，产物位于 `dist/`，不包含参考视频。
