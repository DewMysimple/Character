# ADR-005｜局部坍塌传播与性能缓存

## 状态

`active`

本页关于默认 420 个字符及 120 至 480 调整范围的条款，已由 [[决策/ADR-013-默认160字符与正负60调整范围]] 取代；局部传播、缓存和不通过删减实时对象换取性能的其余结论继续有效。

## 背景

用户希望坍塌像建筑局部失稳：先有一个小区域发生缺失和下沉，再逐步影响周围，而不是整张代码卡片同时坍塌。此前的中心弹簧还会产生过冲，造成字符回弹；字符数量提高后，每帧重复绘制纸张纹理和重复计算随机扰动，也会造成明显卡顿。

## 决策

- 默认使用 `local-collapse`，以代码卡片中部一小处为焦点，按字符到焦点的空间距离安排释放时间，形成由近及远的传播波；传播时长默认约 3.2 秒，以接近参考视频的观察节奏展开。
- 局部模式的每个字符使用独立的确定性释放微偏移、初始横向速度、初始下落速度和扰动相位，避免相邻字符被同步成三字一组；字符被传播波释放后从自己的源位置进入接近零初速的重力下坠，不追踪中心目标、不设置中间汇聚阶段；下落阶段垂直速度不允许反向向上。
- 动画帧出现间隔时，将物理更新拆成最多 60Hz 的子步，防止长帧把多个字符一次性推进过远。
- 保留 `column-collapse`、`center-collapse` 和 `wave-collapse` 作为控制台可切换的文字变化形式。
- `column-collapse` 不再直接使用按字符均匀抽样的源位置。中心连续 5 列作为初始完整缺口窗口，之后以单列为单位按两侧距离连续释放；同一列字符共享释放时刻和列级初始速度，源选择优先纳入完整列，不能把同列拆成零散字母。
- 默认字符数量保持 420，控制台支持 120 至 480；坍塌传播时长默认 3.2 秒，控制台范围为 1.4 至 4.8 秒，变形时长默认 1.05 秒。
- 将静态纸张渐变与纹理缓存为 Canvas，将字符扰动相位在生成时预计算，以降低每帧 CPU 和 Canvas 绘制开销，不减少动态对象。

## 理由

- 局部距离传播能让观众先看到一个明确的失稳源，再观察影响范围扩大；逐字符微偏移能保留结构化传播中的独立物理感。
- 释放后立即下坠保留实时物理因果，同时符合建筑坍方的单向视觉语言；传播延迟只负责表达失稳影响范围，不改变已释放字符的运动方向。
- 整列释放让代码卡片先出现贯穿多行的缺口，再像泄露一样逐列扩展到相邻列；未能组成完整动态列的边缘字符保持在卡片中，避免出现半列的伪坍塌，同时避免多个相邻列同步形成批次。
- 缓存与预计算对最终画面没有可见减法，能够在较高字符量下保持动态密度。

## 影响

- 正面影响：坍塌起点、传播方向和下落过程更容易观察，回弹消失，代码行有更高的字符覆盖密度。
- 代价或风险：传播窗口变长且每个字符独立释放，低重力和极慢播放速度下需要观察花丛触发是否仍能在 8 秒内完成；长帧子步会增加极端卡顿帧的瞬时计算量。

## 验证方式

检查约 1.2 秒只有焦点附近出现缺口，约 2.5 至 3.5 秒缺口向周围扩散且相邻字符不再同步成固定小组；切换 `column-collapse` 后检查中心连续列是否在短窗口内形成完整缺口、列内是否保持同向下落，以及相邻列是否逐列泄露而非批次释放；检查字符下落轨迹不出现垂直回弹或长帧跳跃；检查 420 字符默认配置、四种变化形式、1.4 至 4.8 秒坍塌时长滑块和构建结果；使用 `git diff --check`、`npm run build` 和浏览器页面加载检查性能优化未破坏启动。
