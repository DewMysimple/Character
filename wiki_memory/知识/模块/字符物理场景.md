# 字符物理场景

## 一句话结论

`SceneEngine` 在固定的 720×960 逻辑画布中，用固定 180Hz 子步把字符当作薄片做气动积分、用固定 60Hz 子步更新蝴蝶生态访花和花朵互动，再把结果绘制成纸张色的竖屏构图。

## 适用范围

适用于前 8 秒的自动播放、暂停、重播、时间轴跳转和物理参数调节，以及 8 秒后的蝴蝶持续飞行，不负责编辑器输入或真实字体点云变形。

## 详细内容

### 积分与单位

- 字符物理住在 `src/engine/glyphPhysics.ts`，`scene.ts` 只负责调度。位置为 px、速度为 px/s、加速度为 px/s²，**不再是「每 60Hz 帧多少像素」**。
- `advance()` 用累加器把时间切成固定 `PHYSICS_DT = 1/180` 的子步驱动 `stepGlyphs`，再把这些真实执行的子步累计到 `AGENT_DT = 1/60` 驱动 `stepAgents`。代理增量不能使用被 `SCENE_DURATION` 封顶的 `time` 差，否则 8 秒后会冻结；也不能改回每个显示帧一次，否则状态机会产生刷新率差异。`seek()` 复用两套累加器。
- 每个字符是一块薄片：迎风分量与掠风分量分别乘不同阻力系数形成各向异性阻力，力矩取 `vn * vt` 乘积项，自发产生「兜风—减速—打滑—翻转」。**不要再添加人工 flutter/turbulence 正弦或让重力随时间增大**，那些是这个模型出现之前的替代品。
- 空气是由标量势解析求导得到的无散度 curl noise 场，在 24×32 粗网格上以 20Hz 预计算并双线性采样。气动力作用在相对风速 `v - v_air` 上，字符被涡旋卷着走，相邻字符因此同向旋绕。
- 字形质量与迎风面积由 `measureText` 的墨迹包围盒推出并按全字符集均值归一化，收尾速度按 `sqrt(mass / dragArea)` 分层。`primeGlyphMetrics` 在 `buildGlyphs` 中调用。
- `tilt` 是离面倾角，由同一股气流驱动并叠加指向正面姿态的恢复力矩，使字符大部分时间朝向观众、偶尔翻面。

### 传播与渲染

- 默认 160 个字符从代码卡片各行取样，控制台范围为 100 至 220、步长为 10；字符从卡片中部的一小处开始缺失，按空间距离逐步传播到周围。字符一旦释放就从原始列受重力下坠，不追踪坍塌中心、不减速汇聚，位移严格单向。`center-collapse` 与 `wave-collapse` 只改变释放传播顺序。`column-collapse` 是独立的整列缺口模式：中心连续 5 列在短窗口内依次打开，之后以单列为单位向外连续泄露；同一列字符共用释放时刻和列级初始速度，源字符选择优先保留完整列，未纳入动态列范围的边缘字符保持静态，防止列内出现抽样缺口和多列批次同步。
- 字符只有在达到 650 至 776 的花丛高度并完成最小下落时间后才进入变形窗口；字符降低透明度，蝴蝶根据对应出生点提高透明度，在花丛上方的分散飞行层持续盘旋，并保留对应花朵的触发关系。
- 蝴蝶的 `flightPhase` 只负责轨道呼吸和细微漂移，`wingPhase` 负责扇翅；`PhysicsConfig.wingBeatFrequency` 以 Hz 控制扇翅频率。`flightMode` 依次经历 `approach`、`orbit`、`hover`、`transfer`：接近阶段减速到达花头，环绕阶段根据当前位置在椭圆上的相位计算切向速度和径向回正，悬停阶段靠近花心，转访阶段从至多六个已开放邻花中按距离与拥挤度加权选目标。`homeFlowerId` 只保存出生花朵和首次触发关系，`targetFlowerId` 是当前花朵。`butterflyVisitDuration` 控制驻花时长，`butterflySeparation` 控制 26px 内的成对分离；软边界力先转向，只有越出紧急边界才回弹。
- `ScenePointer` 由 `AnimationCanvas` 从 Pointer Events 坐标转换而来，通过 `SceneEngine.setPointer` 直接进入引擎。花朵用 `windPhase`、`pointerOffset` 和 `flowerWindStrength` 生成自然风动与局部横向涟漪；`getFlowerPose` 将根部、枝条控制点和花头终点计算为同一条二次曲线，`pointerOffset` 参与枝条末端姿态，花瓣绘制在曲线终点，叶片沿曲线取点，保证根部固定且整株连接。蝴蝶在 `butterflyPointerRadius` 内按 `pointerFalloff` 受到 `butterflyPointerRepulsion` 的远离力，并在影响期间暂停 `stateUntil`；指针离开后保持 `targetFlowerId`，先切换为 `approach` 回到花头。所有响应都在 Canvas 循环内完成，不触发 React 每帧重渲染。
- 蝴蝶达到花朵触发区域后，花茎、叶片、花瓣按进度依次绘制。
- 花茎由 `Flower` 自身绘制；不要再叠加没有花朵对应关系的独立 `StemSeed` 集合，否则完成态会出现空根。
- 花园进度在 8 秒时完成，`motionTime` 继续增长，因此花朵完成不会停止蝴蝶运动。
- 花朵颜色、字符颜色和布局都来自固定随机种子，便于复播比较。
- `AnimationCanvas.tsx` 负责 ResizeObserver、高 DPI 尺寸和动画循环清理；React 只接收低频快照。

### 无损性能路径

- `buildGlyphs` 同时建立按 `releaseAt`、ID 稳定排序的释放队列。字符释放后进入按 ID 排序的 `liveGlyphs`；变形完成或叙事时钟到达 8 秒后标记 `retired`，保留调试数据但退出气流、积分和渲染热路径。不要通过提前生成蝴蝶来清空尾部字符，否则会改变完成态轨迹。
- 代码卡片使用静态底层和透明源码层两个缓存，缓存比例由 `AnimationCanvas` 传入的实际 `DPR × fitStage.scale` 决定。释放时只清除源码单元，交接淡出仍实时绘制；seek、重播、结构参数重建和比例变化会重建缓存并重放当前缺口。
- `AirField.sampleInto` 使用一个可复用输出对象同时返回 X/Y，避免重复定位同一气流网格。花头坐标在每个 60Hz 代理步只按花朵计算一次，蝴蝶共享读取；生成瞬间仍直接采样花头，保持原交接时刻。
- 蝴蝶分离网格的单元尺寸等于 26px 影响半径。每只蝴蝶只查询相邻九格，再按 ID 排序候选，保证力累加顺序与旧 `first → second` 暴力循环相同。目标花占用量、网格链和分离力数组均复用。
- 暂停后的 requestAnimationFrame 仍保留轻量调度，但不调用 `advance` 或 `render`；参数、播放、seek、重播和 ResizeObserver 通过 `needsRenderRef` 使下一帧失效重画。完全相同的快照不会重复发送到 React。

## 常见问题或陷阱

- 不要在 Canvas 的每一帧直接写 React state，否则会造成不必要的树重渲染。
- 修改粒子数量后要重新初始化场景，不能把旧粒子数组继续累加。
- 坍塌时长和变形时长影响蝴蝶出生时机和花朵触发密度，调参后需要重新检查 1.4 至 6.5 秒区间；高字符数量下要同时观察 Canvas 帧率和文字行的覆盖密度。8 秒完成态仍要检查蝴蝶是否持续更新，以及范围、风力、中心吸引和扇翅频率是否无需重播即可响应。纸张背景纹理与粒子扰动已分别缓存和预计算，避免把性能优化转化为减少动态对象。
- 指针事件只在 Canvas 上监听并在卸载时移除；面板覆盖区域不应继续传递场景指针。指针关闭或离开后，花朵使用回归速度回到自然风动，蝴蝶使用回归转向回到各自花朵，不要通过重播或重建粒子实现恢复。
- 调整花朵指针互动时，先确认 `drawFlower` 的枝条终点与花头使用同一个 `getFlowerPose`，根部保持固定，叶片从同一条枝条曲线取点；不要把 `pointerOffset` 只加到花头，也不要另建一套脱离枝条的主体坐标。
- 调整 `column-collapse` 时，先确认中心缺口的每一列包含该列全部可见字符，再确认同一列的 `releaseAt` 完全一致、相邻列的 `releaseAt` 有连续差异；不要在列模式复用按字符均匀抽样的源位置计划，也不要为同列加入独立释放抖动或让多列共享批次时刻。
- `depth` 是**渲染期投影**，不是物理量。任何需要知道字符「看起来在哪」的地方都必须走同一个 `projectGlyph`：变形判定用投影后的 y，`spawnButterfly` 用投影后的位置，否则蝴蝶会在变形瞬间跳位。字符和蝴蝶速度现在都是 px/s，交接时只保留受限比例，不再除以 60。
- `erosionIrregularity`、`glyphMassVariance`、`glyphDepth` 在 `buildGlyphs` 时写进字符，必须留在 `setConfig` 的重建分支里；其余新参数是每步读取的实时系数，加进重建分支只会让拖动滑杆时反复重放。
- 逐字符释放扰动是**加性局部抖动**，不是与整个跨度做混合。混合会让中心字符与边缘字符在接近时刻释放，整张卡片同时溶解而不是一个洞逐渐长大。
- 伪 3D 前缩设有易读性下限 `MIN_FORESHORTEN`：完全物理前缩会让 broadside 姿态（最常见姿态）压成一条线而消失。调大 `glyphTilt` 或调小倾角恢复系数都会让字符频繁压扁难以辨认。
- 用 `harness.html?check=1` 跑十五项自动检查：除原有行为检查外，还覆盖字符退役与 DPR 缓存重建、空间网格和暴力算法力一致性、默认/上限字符的 2× DPR P95。用 `harness.html?t=1.3,1.8,2.4&cols=3&scale=0.62` 抓帧与参考帧比对。harness 不被 `npm run build` 打包。
