# 薄片气动翻滚与伪 3D 渲染

## 用户问题

用户提出文字坠落「物理模拟很粗糙」，要求重新设计优化；随后进一步追问引入 p5.js 等技术能否提高质量和上限。

## 根因

逐帧对照 `_analysis_frames/gap-analysis-2026-09-01/reference/05_2.5s.jpg` 与当时实现，确认粗糙感来自模型缺失而非参数：

- `scene.ts` 的 `v *= config.drag` 每帧乘一次且未按 delta 归一化，144Hz 屏幕上阻尼是 60Hz 的 2.4 倍。
- `vy = Math.max(0, vy)` 硬夹断，字符不能有任何瞬时上浮。
- 湍流是每字符独立的一维正弦，无空间相关性，只有抖动没有涡旋。
- 重力写成随时间增大的 magic number 斜坡，用于补偿不真实的阻尼。
- 旋转匀速自转，与速度和受力完全解耦。
- 所有字符共享同一质量与迎风面积。
- `substeps = ceil(delta*60)` 在 60Hz 下恒为 1，等于没有子步；`seek()` 用 1/60 而实时播放用变步长。

另发现脱落瞬间的视觉断裂：卡片文字 `10px`/`left`/`CODE_PALETTE[(line*7+col)%6]`，掉落粒子 `12px`/`center`/`CODE_PALETTE[index%6]`，且 alpha 从 0 硬跳到 0.96。

## 关于引入库的结论

不引入。飘落薄片的主导物理是空气动力学：Matter.js、Rapier2D、Box2D、Planck 只提供各向同性阻尼，不感知姿态，无法产生兜风翻滚；XPBD 求解约束，而自由下落的独立字符之间没有约束；p5.js 不提供任何物理，`noise()` 与 `p5.Vector` 均可低成本替代，WEBGL 在 150 字符规模下无意义。参考帧实测散落字符仅 100 至 150 个，Canvas2D 远未到瓶颈，因此上限提升改在渲染侧完成。

## 实现

- 新增 `src/engine/math.ts`（共享 `clamp`/`seededRandom`/缓动，避免新模块与 `scene.ts` 循环引用）与 `src/engine/glyphPhysics.ts`（字形度量缓存、curl noise 气流场、薄片气动积分）。
- `advance()` 改为固定步长累加器：字符以 `PHYSICS_DT = 1/180` 积分（`stepGlyphs`），蝴蝶花朵指针每帧一次（`stepAgents`）。`seek()` 复用同一套子步。顺带把蝴蝶阻尼改为 `0.982 ** (delta*60)`。
- 薄片气动模型取代 `flutter`/`turbulence`/`verticalJitter` 三个人工正弦与重力斜坡；力矩取 `vn * vt` 乘积项。气动力作用在相对风速上，字符被无散度涡旋场卷着走。
- 质量与迎风面积由 `measureText` 墨迹包围盒推出并按全字符集均值归一化。
- 新增离面倾角 `tilt` 与恢复力矩，配合渲染期 `cos(tilt)` 前缩实现伪 3D 翻面；新增 `depth` 景深投影与运动模糊残影。
- 单向性由「速度非负」改为「位移单向」：限制瞬时上冲幅度，并硬保证 `y >= releaseY`。
- 脱落连续性：卡片与粒子统一 `GLYPH_FONT`、统一取色 `getGlyphColor`、粒子按半个字宽偏移抵消对齐差、alpha 在 0.18s 内渐入。
- 逐字符释放扰动由跨度混合改为加性局部抖动；缺口前沿半径由角向噪声调制成不规则瓣状。
- `PhysicsConfig` 新增 9 项参数，控制台「文字坍塌」拆为「文字坍塌 / 坠落物理 / 字符渲染」三组。其中 `erosionIrregularity`、`glyphMassVariance`、`glyphDepth` 在构建期写入字符，加入 `setConfig` 的重建分支。
- 新增 `harness.html` + `src/harness.ts` 校准工装：`?t=` 抓帧比对，`?check=1` 跑自动检查。不被 `npm run build` 打包。
- 删除被新模型取代的死字段：`PhysicsConfig.drag`（原为字符每帧乘法阻尼，现由 `terminalVelocity` 表达，且从未出现在控制面板）、`GlyphParticle.flutterPhase` 和 `turbulencePhase`（人工正弦的相位，正弦本身已删除）。蝴蝶阻尼保持原有系数不变。

## 验证

- `npm run build` 通过；产物 230.25 kB，与改动前 230.15 kB 基本持平，模块数仍为 35（确认 harness 未进入产物）。
- `harness.html?check=1` 八项全部通过：
  - 位移单向：最大上升 0.0000px
  - 60Hz 与 144Hz：4 秒后漂移 **0.000px**（原实现此项差异显著）
  - seek 与播放一致：3s 处 2.197px
  - 复播确定性：0px
  - 8 秒花园：36/36 朵开放，420 只蝴蝶
  - 整列缺口完整：0 列出现时刻分裂
  - 相邻去批次化：326 对相邻字符中仅 13 对在 8ms 内
  - 单帧成本：1.80ms（含渲染与运动模糊，330 个活跃字符，软件渲染下测得）
- 抓帧比对 1.3/1.8/2.4/3.0/3.8/5.0 秒：缺口从中心小孔逐步长大、外围代码保持可读，与参考视频结构一致；2.6 秒放大帧可见字符各自翻滚、部分前缩翻面、成团旋绕。
- `column-collapse` 抓帧确认整列缺口贯穿 12 行并按单列向外泄露。
- 未减少字符、蝴蝶、花朵或任何实时动态对象；未改动蝴蝶飞行、花朵生长与指针互动逻辑。

## 结果

字符坠落从「按帧缩放 + 人工正弦」换成真实单位的薄片气动模型加无散度涡旋场：字符自发翻滚、相邻字符成团旋绕、按字形出现速度分层，缺口呈有机侵蚀形状，脱落瞬间不再变大位移换色硬闪。渲染侧另加伪 3D 翻面、景深分层与运动模糊，超出参考视频的 2D 自转质感。帧率依赖 bug 一并消除。
