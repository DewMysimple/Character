# ADR-001｜Canvas 与 React 控制壳

## 状态

`active`

## 背景

场景包含大量字符、蝴蝶和植物线稿，需要稳定的逐帧绘制；同时还需要可读、可操作的播放和参数面板。

## 决策

用原生 Canvas 承担场景绘制和粒子更新，用 React 管理控制台、参数状态和低频场景快照。通过 ref 把连续变化的参数传递给引擎。

## 理由

- 避免为每个动画对象创建 DOM 节点，适合字符粒子和线稿。
- React 控制壳便于实现表单、键盘快捷键、响应式面板和无障碍状态。
- 不引入额外物理库，保留对视觉节奏和绘制风格的直接控制。

## 影响

- 正面影响：依赖少、构建小、运行路径清晰。
- 代价或风险：Canvas 内对象不能直接被 DOM 检查，需要通过场景快照观察状态。

## 验证方式

运行 `npm run build`，并在浏览器中检查 0 秒、1.5 秒、2.8 秒、3.5 秒和 5 秒的阶段与构图。
