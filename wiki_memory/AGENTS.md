# Character 工程记忆维护协议

本文件沿用工程记忆构建模板，用于指导后续 Agent 维护本仓库的持久化记忆。

## 记忆模型

- `当前状态/`：当前有效的项目事实，每个主题保持一个 active 页面。
- `决策/`：架构、技术选型和会影响后续工作的工程决策。
- `知识/`：稳定的模块说明、开发流程、规范和运维知识。
- `日志/`：一次实质任务的追加式历史记录，不作为当前事实的唯一来源。
- `AGENTS.md`：本协议以及记忆读写规则。

原始代码、配置、README 和本地参考资料是事实来源。记忆中记录结论、关系和相对路径，不复制大段原文。

## 会话开始读取顺序

1. 读取本文件。
2. 读取 `当前状态/项目概览.md`、`当前状态/系统架构.md`、`当前状态/当前约束.md`、`当前状态/当前待办.md`。
3. 读取与当前任务相关的 active 决策。
4. 读取相关知识页。
5. 只有需要追溯时才读取最近 1 至 3 篇日志。

## 写入规则

- 完成实质任务后新增 `日志/YYYY-MM-DD-任务标题.md`，并更新 `日志/MOC_工作日志.md`。
- 长期页面必须使用 YAML frontmatter，包含 `type`、`status`、`kind`、`importance`、`updated`、`topic`、`source_logs` 和 `supersedes`。
- 新结论替代旧结论时，标记旧页面为 `superseded` 或 `deprecated`，不删除历史。
- 每次项目修改都要在日志中记录文件变更、验证结果和远程同步状态。

## Git 约定

项目根目录 `AGENTS.md` 规定每次修改后提交并推送至 `origin`。推送失败必须报告准确原因。
