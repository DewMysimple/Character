# 2026-09-01｜重构蝴蝶生态访花机制

- 时间：2026-09-01（北京时间）
- 类型：`feature`
- 状态：`完成`
- 目标：把蝴蝶从无目的周期目标追逐改为被花朵吸引、环绕、悬停并转访邻花的确定性生态行为。
- 日志索引：[[日志/MOC_工作日志|工作日志 MOC]]

## 根因与实现

- 旧机制让横向和纵向使用不同频率生成目标，并叠加宽幅漂移；速度追踪后形成李萨如式乱转，花朵只是坐标来源而不是可读的行为目标。
- 新增 `approach → orbit → hover → transfer` 状态机。接近使用减速到达，环绕使用径向回正与切向速度，悬停靠近花心，转访在至多六个邻花中按距离和拥挤度确定性选择。
- 保留 `homeFlowerId` 负责首次花朵触发，使用 `targetFlowerId` 表示当前访花目标；新增 26px 局部分离和软边界转向。
- 蝴蝶速度改为 px/s，代理层改为固定 60Hz；指针排斥暂停访花计时，结束后保持当前目标并先回花。
- 新增默认 `5.5s` 的驻花时长和默认 `0.85` 的群体避让参数，完成态实时生效。

## 文件变更

- `src/engine/scene.ts`、`src/engine/types.ts`：生态状态机、邻花选择、固定代理累加器、分离/边界力、指针恢复和新配置。
- `src/components/ControlPanel.tsx`：将模式说明改为“生态访花”，增加“驻花时长”“群体避让”，并把“花朵跟随”改名为“花朵吸引”。
- `src/harness.ts`、`README.md`：工装扩展为十二项检查，并记录生态机制和运行单位。
- `wiki_memory/`：新增 ADR-014，并同步当前状态、约束、架构和模块知识。

## 测试与验证

- `npm run build`：通过，TypeScript 与 Vite 生产构建成功。
- `harness.html?check=1`：十二项全部通过；完成态 12 秒采样中 `98.4%` 位于目标花朵 135px 内，`100.0%` 完成至少一次转访，单花最大目标数 `9`，10px 内重叠率 `0.15%`，单步最大位移 `2.03px`。
- 代理一致性：60Hz 与 144Hz 运行 8 秒后位置漂移 `0.000px`、状态不匹配 `0`；指针移开 4 秒后测试蝴蝶回到同一目标花朵的 `orbit` 状态，距花头 `51.2px`。
- 性能：默认 160 字符场景的工装单帧成本 `0.92ms`；100、160、220 三档仍分别生成等量蝴蝶并开放 36/36 朵花。
- 视觉检查：在 1440×1000 视口以 `0.25x` 比较完成态前后 Canvas，轨迹围绕花头连续变化；375×812 视口无横向溢出，面板内部滚动正常，新参数恢复默认后时间轴仍为 `8.00s`。

## 结果与下一步

- 结果：蝴蝶的运动现在能读出花朵吸引、局部闭合环绕、花心停留和错峰邻花转访，不再由宽幅随机目标主导。
- 下一步：如继续调校，优先使用驻花时长、花朵吸引和群体避让，不要重新叠加独立横纵频率的宽幅目标漂移。
