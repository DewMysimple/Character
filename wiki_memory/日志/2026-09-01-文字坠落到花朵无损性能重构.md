# 2026-09-01｜文字坠落到花朵无损性能重构

## 目标

在不减少默认 160 个字符、蝴蝶、花朵、180Hz 物理、2× 高 DPI、两层残影和生态访花效果的前提下，降低文字坠落、变蝶和花朵生长过程的主线程开销。

## 变更

- 字符增加退役状态和稳定释放队列，只对 `liveGlyphs` 执行气动积分与绘制；8 秒边界保留原蝴蝶出生时刻，只清理尚未淡完的尾部字符。
- 代码卡片拆成按实际渲染比例构建的底层与源码缓存，释放时增量清除对应单元，保留 0.18 秒实时交接淡出。
- 气流改为一次二维采样；花头在代理步内共享；目标花占用量、分离力和网格链使用复用数组。
- 蝴蝶分离改成 26px 确定性空间网格，并按 ID 恢复旧算法的力累加顺序。
- 花瓣使用绝对椭圆坐标，暂停状态停止重复 Canvas 重画，相同快照不再重复提交 React；删除外层重复清屏。
- 扩展 harness 至十五项，新增退役/缓存、空间网格力一致性和 2× DPR P95 检查。

## 验证

- `npm run build`：通过。
- `harness.html?check=1`：十五项全部通过；字符 160/160 退役、空间网格力误差 0、候选约 483/12,720。
- 2× DPR：默认与 220 字符 P95 均远低于 8.3ms/16.6ms 预算；独立 4× CPU 降速复核默认 P95 为 4.2ms。
- 优化后 3.2 秒 `fillText` 约 357 次，原实现约 880 次；8 秒完成态从约 576 次降至 1 次。
- 0.8、1.2、2.4、4.8、8.0 秒关键帧与优化前 SSIM 最低 0.999254；0.1×/0.25× 实时慢放最大字符单帧位移为 1.02px/5.24px，无跳位和交接断层。
- 暂停 500ms 内 Canvas 清屏/重绘 0 次，继续后 250ms 内恢复 7 次绘制。
- `git diff --check`、版本库产物检查和最终状态检查：通过。

## 取舍

- 实测完整 `setTransform` 直写会让 Canvas 成本从约 0.51ms 回升到 1.06ms，因此保留浏览器优化更好的局部 `save/transform/restore`。
- 批量推进空的 180Hz 时钟会在浮点边界多执行一个子步并改变完成态轨迹，因此保留原固定步累加；字符循环已经在无存活对象时立即返回。
- 不引入 Worker、OffscreenCanvas、WebGL 或新依赖，不通过降低质量或兼容性换性能。
