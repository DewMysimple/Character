# 参考视频校准与逐字符坍塌物理

## 目标

根据 `C:\Users\Administrator\Desktop\差距分析\当前状况.mp4` 和 `C:\Users\Administrator\Desktop\差距分析\原视频参考.mp4` 的逐帧对照，改进文字坍塌的传播节奏、单字独立性和实时物理稳定性。

## 问题

- 当前视频中约 1.5 至 2.5 秒就完成大部分中心缺口扩张，参考视频在约 2.5 至 3.5 秒仍处于持续传播和下落阶段。
- 当前相邻字符的释放时间过于接近，用户观察为三个字一起坍塌，缺少逐字独立的失稳差异。
- 当前字符初始下落速度和加速度偏强，长帧时单步更新可能放大跳跃感。
- 源文字原先在字符激活后立即隐藏，缺口交接过硬。

## 实现

- 将默认 `collapseDuration` 从 1.4 秒调整为 3.2 秒，并把面板范围扩展到 1.4 至 4.8 秒。
- 新增统一的坍塌起始时间和动态阶段结束计算，使 falling 阶段跟随传播窗口，而不是固定在较早时间切换。
- 默认局部模式使用每字符确定性正向释放微偏移，避免负偏移被起始时间下限夹成同步；每字符保留独立初始横向速度、初始垂直速度和扰动相位。
- 将字符下落加速度降低到渐进重力曲线，初速接近零，保留 `vy >= 0` 单向约束并降低速度上限。
- 源文字在 0.14 秒短窗口中淡出，和从源位置出发的字符粒子交叉衔接。
- `advance()` 对长帧执行最多 60Hz 的子步积分，避免帧间隔抖动造成位置跳跃。
- `column-collapse` 继续保持完整列组共享释放时刻，未改变整列缺口模式的结构语义。

## 验证

- `npm run build` 通过。
- 开发服务器 `http://127.0.0.1:5173/` 返回 HTTP 200。
- 代码差异已检查，未减少字符、蝴蝶或花朵数量。
- 本次仅修改源代码、README 和工程记忆，未把视频、分析帧、`node_modules` 或 `dist` 加入版本库。

## 结果

默认坍塌拥有更长的可观察传播窗口，局部模式的字符释放从组同步改为逐字符独立；整列模式仍可用于表达贯穿多行的结构性缺口。下落物理保持单向，不添加回弹或中心汇聚。
