# 当前约束

## 技术约束

- 使用 React、ReactDOM、Vite 和 TypeScript；运行时不引入 Matter.js、p5.js 或大型动画库。
- 动画主体使用原生 Canvas，蝴蝶和花朵采用程序化线稿，不依赖外部图片。
- 只对 Canvas 中的位移、旋转和透明度做动画；参数控制由 React 状态和 ref 传递。

## 兼容性约束

- Canvas 使用高 DPI 适配，并保持 3:4 竖屏构图比例。
- 桌面端控制台位于右下角，移动端转为底部面板，不能遮挡主要动画。
- 支持空格键播放或暂停和 `R` 键重播；不得因为系统的 `prefers-reduced-motion` 设置自动停止或降级本实验的动态效果。

## 质量约束

- 每次修改都必须完成相关验证、创建 Git 提交并推送至 `origin`。
- 随机布局使用固定种子，重播不能累积粒子，刷新后布局可比较。
- 花园生长时间轴为 8 秒，花园完成后蝴蝶仍需持续运动。
- 字符必须先从卡片中心坍塌并掉落一定距离，进入花丛高度后才允许替换成蝴蝶。
- 蝴蝶扇翅频率必须由参数面板控制，默认使用较慢的 2.8Hz 线稿节奏。
- 默认字符数量为 420，目标是让代码卡片各行具有连续的可坍塌字符密度；面板允许在 120 至 480 之间调节。
- 默认文字变化必须从局部缺口开始向周围传播，不能让整张代码卡片同时坍塌；面板仍允许切换同列坍方、中心聚拢和波纹塌落。
- 坍塌过程必须单向推进且不产生回弹；性能优化应通过缓存和预计算完成，不得减少字符、蝴蝶或实时动态数量。
- 不将原始 MP4、分析帧、`node_modules` 或 `dist` 提交到远程仓库。

## 操作边界

- 参考视频和文字稿只用于观察和分析，不把视频作为背景或构建资源。
- 不擅自覆盖或删除用户已有的参考资料和无关改动。
- 推送失败必须报告准确原因，不得声称远程同步已完成。
