# ADR-010｜参考视频校准与逐字符坍塌物理

## 状态

`active`

## 背景

逐帧对照 `差距分析/当前状况.mp4` 与 `差距分析/原视频参考.mp4` 时发现，当前文字坍塌在约 1.5 至 2.5 秒内过快扩大，且相邻字符的释放时间过于接近，容易被读成几个字符组成一个僵硬单元。参考视频在中心缺口形成后仍保留较长的逐步传播和下落尾迹。

## 决策

- 默认 `local-collapse` 的传播时长改为 3.2 秒，控制台允许 1.4 至 4.8 秒，让缺口从中心到外围有可观察的持续过程。
- 每个局部字符使用固定种子生成独立的释放排序扰动、初始横向速度、初始下落速度和扰动相位。空间距离仍然保留局部传播方向，但不再单独决定释放时刻，因此等距字符不会锁成三字一组或规律横排。
- 字符释放后以接近零的垂直初速开始，使用单向半隐式 Euler 重力积分逐步加速；保留垂直速度非负约束，不添加回弹或中心重新汇聚。
- 源文字使用短交接淡出，不在激活瞬间硬切；字符粒子仍从自己的原始位置出发并保持完整动态数量。
- `advance()` 在长帧时拆分物理子步，降低浏览器帧间隔不稳定造成的跳跃；正常帧不额外扩大更新成本。
- `column-collapse` 继续作为有意的结构化模式，保持同一完整列共享释放时刻，但不再让四列或其他多列批次共享时刻；逐字符独立释放属于默认局部模式及其他非整列模式，列模式则使用逐列连续泄露。

## 理由

参考视频的差距主要来自时间曲线、释放粒度和下落尾迹，而不是粒子数量。将传播时间与字符的独立物理初始状态分开，可以同时保留局部失稳的结构和单字粒子的自然差异。子步积分改善长帧稳定性，不需要删减字符或降低实时动态密度。

## 影响

- 正面影响：中心缺口更容易被观察，外围字符不会过早同时消失；逐字释放排序、逐列泄露、独立旋转和更明显的横向初速使坍塌不再像固定小组或成行移动。
- 代价或风险：更长的传播时长会让部分字符在更晚时间才进入花丛，需要持续检查 8 秒花园是否仍能完成；长帧子步在极端卡顿时会增加瞬时更新次数。
- 兼容性：整列模式的完整列组语义不变，蝴蝶生成、花朵生长、完成态飞行和指针互动不改变。

## 验证方式

检查默认模式在约 1.2 秒只出现中心小缺口，2.5 至 3.5 秒逐渐向外传播；逐帧确认相邻字符不再同帧同步成固定三字单元，释放后的垂直位移单调向下；在低帧率或长帧下确认粒子不跳跃；检查 `column-collapse` 按完整列释放但相邻列不再批次同步；运行 `npm run build`、`git diff --check`、记忆 lint、产物检查和开发服务器 HTTP 检查。
