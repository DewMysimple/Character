# ADR-005｜局部坍塌传播与性能缓存

## 状态

`active`

## 背景

用户希望坍塌像建筑局部失稳：先有一个小区域发生缺失和下沉，再逐步影响周围，而不是整张代码卡片同时坍塌。此前的中心弹簧还会产生过冲，造成字符回弹；字符数量提高后，每帧重复绘制纸张纹理和重复计算随机扰动，也会造成明显卡顿。

## 决策

- 默认使用 `local-collapse`，以代码卡片中部一小处为焦点，按字符到焦点的空间距离安排释放时间，形成由近及远的传播波。
- 字符被传播波释放后立即从自己的源位置进入重力下坠，不追踪中心目标、不设置中间汇聚阶段；下落阶段垂直速度不允许反向向上。
- 保留 `column-collapse`、`center-collapse` 和 `wave-collapse` 作为控制台可切换的文字变化形式。
- `column-collapse` 不再直接使用按字符均匀抽样的源位置。中心连续 5 列作为第一组完整缺口，之后按两侧各 4 列分组释放；每组列内字符共享释放时刻和列级初始速度，源选择优先纳入完整列组，不能把同列拆成零散字母。
- 默认字符数量提高到 420，控制台支持 120 至 480；坍塌时长默认 1.4 秒，变形时长默认 1.05 秒。
- 将静态纸张渐变与纹理缓存为 Canvas，将字符扰动相位在生成时预计算，以降低每帧 CPU 和 Canvas 绘制开销，不减少动态对象。

## 理由

- 局部距离传播能让观众先看到一个明确的失稳源，再观察影响范围扩大。
- 释放后立即下坠保留实时物理因果，同时符合建筑坍方的单向视觉语言；传播延迟只负责表达失稳影响范围，不改变已释放字符的运动方向。
- 整列释放让代码卡片先出现贯穿多行的缺口，再像泄露一样扩展到相邻列；未能组成完整动态列组的边缘字符保持在卡片中，避免出现半列的伪坍塌。
- 缓存与预计算对最终画面没有可见减法，能够在较高字符量下保持动态密度。

## 影响

- 正面影响：坍塌起点、传播方向和下落过程更容易观察，回弹消失，代码行有更高的字符覆盖密度。
- 代价或风险：局部传播会让远离焦点的字符更晚释放，低重力和极慢播放速度下需要观察花丛触发是否仍能在 8 秒内完成。

## 验证方式

检查约 1.6 秒只有焦点附近出现缺口，约 2.6 秒缺口向周围扩散；切换 `column-collapse` 后检查中心连续列是否整组消失、列内是否保持同向下落，以及相邻列是否按组泄露；检查字符下落轨迹不出现垂直回弹；检查 420 字符默认配置、四种变化形式、坍塌时长滑块和构建结果；使用 `git diff --check`、`npm run build` 和浏览器页面加载检查性能优化未破坏启动。
