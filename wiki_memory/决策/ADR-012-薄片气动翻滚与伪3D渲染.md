# ADR-012｜薄片气动翻滚与伪 3D 渲染

## 状态

`active`

本决策只取代 ADR-010 的「垂直速度非负约束」一条，ADR-010 的传播时长、逐字符独立释放和源文字交接淡出结论继续有效。ADR-011 的整列缺口语义完全不变。

## 背景

用户指出文字坠落「物理模拟很粗糙」，并追问引入 p5.js 等库能否提高质量上限。

逐帧对照 `_analysis_frames/gap-analysis-2026-09-01/reference/` 后确认，参考视频里散落字符只有 100 至 150 个，与卡片文字同字号同配色，脱离后在缺口下方形成滞留较久、成团旋绕的字云，每个字符自身在翻滚。当时的实现与之相比有六个可定位的技术缺陷：

- `drag` 以每帧一次的乘法施加，没有按 delta 归一化，144Hz 屏幕上的阻尼是 60Hz 的 2.4 倍。
- `vy = Math.max(0, vy)` 硬夹断，字符不能有任何瞬时上浮，飘落感被从根本上消除。
- 湍流是每字符独立的一维正弦，没有空间相关性，只能产生抖动而不是涡旋。
- 重力写成随时间增大的 magic number 斜坡，用于补偿不真实的阻尼。
- 旋转是匀速自转，与速度和受力完全解耦。
- 所有字符共享同一质量与迎风面积。

## 决策

### 不引入外部库

飘落薄片的主导物理是空气动力学，不是碰撞也不是约束。Matter.js、Rapier2D、Box2D、Planck 都只提供各向同性的 `linearDamping` / `angularDamping`，不感知姿态，因此无法产生兜风翻滚；XPBD 求解的是约束，而自由下落的独立字符之间没有约束；p5.js 不提供任何物理，其 `noise()` 与 `p5.Vector` 均可低成本替代，WEBGL 模式在 150 个字符规模下没有意义。引库只会带来重写渲染层与 React 生命周期冲突的代价。参考视频提到 xPBD 对应的是「解药」的弹性薄膜，与本场景不是同一类问题。上限提升改在渲染侧完成，字符量维持 420、维持 Canvas2D。

### 物理模型

- 新增 `src/engine/glyphPhysics.ts`，字符物理使用真实单位（px、秒、px/s²），由 `SceneEngine` 以固定 180Hz 子步积分；蝴蝶与花朵是运动学对象，仍按帧更新。
- 每个字符建模为薄片：迎风分量 `vn` 与掠风分量 `vt` 分别乘以压差阻力系数与摩擦阻力系数（比值约 16:1），产生各向异性阻力；力矩取 `vn * vt` 乘积项，自发产生「兜风—减速—打滑—翻转」的往复。因此删除原有的 `flutter`、`turbulence`、`verticalJitter` 三个人工正弦和重力斜坡。
- 空气使用由标量势解析求导得到的无散度速度场（curl noise），在 24×32 粗网格上以 20Hz 预计算并双线性采样。气动力作用在相对风速 `v - v_air` 上，字符被涡旋卷着走，相邻字符因此共享同一个涡旋方向。
- 字形质量与迎风面积由 `measureText` 的实际墨迹包围盒推出，按全字符集均值归一化，收尾速度按 `sqrt(mass / dragArea)` 分层。
- 增加离面倾角自由度 `tilt`，由同一股气流驱动，并叠加指向正面姿态的恢复力矩，使字符大部分时间朝向观众、偶尔翻面。

### 单向性约束改为位移单向

原「垂直速度非负」放宽为「位移单向」，完整保留其原始意图（禁止减速上浮与向中心重新汇聚）：允许兜风一拍内的瞬时上冲但限制其幅度，同时硬保证字符的 `y` 永不小于其脱落时的 `releaseY`。净下落仍严格单调。

### 渲染

- 伪 3D 翻滚：以 `cos(tilt)` 作为前缩系数写入变换矩阵，`sy` 过零时字符翻到背面。前缩设有易读性下限，因为完全物理前缩会让 broadside 姿态（最常见姿态）压成一条线而消失，这是有意的艺术妥协。
- 景深分层：`depth` 作为渲染期投影而非物理量，物理保持平面与确定性。凡是需要知道字符「看起来在哪」的地方（变形判定、蝴蝶生成）都必须走同一个 `projectGlyph`。
- 运动模糊：沿速度反方向叠加两个残影，并同步回卷姿态，使拖影跟随翻滚而非平移。

### 释放排序改为局部加性抖动

逐字符扰动由「与整个跨度做混合」改为「加性局部抖动」。原混合方式会让中心字符与边缘字符在接近的时刻释放，导致整张卡片同时溶解而不是一个洞逐渐长大；加性抖动仍足以打散相邻字符，同时保持失稳前沿紧凑。缺口前沿半径另由角向噪声调制，使洞口呈不规则瓣状。

## 理由

粗糙感的根因是模型缺失而非参数不好：没有姿态相关的阻力就不可能有翻滚，没有空间相关的流场就不可能有成团旋绕。补上这两项之后，原先用来手工模仿这些现象的正弦项全部可以删除，代码反而更短更可解释。固定步长同时消除了帧率依赖，使同一场景在不同刷新率显示器上表现一致。

## 影响

- 正面影响：字符呈现真实的翻滚与涡旋；`.` `i` 与 `W` `@` 出现自然的速度分层；缺口从规整椭圆变为有机侵蚀形状；脱落瞬间不再变大、位移、换色或硬闪；60Hz 与 144Hz 的漂移由显著降为 0.000px。
- 代价或风险：字符大部分时间朝向观众依赖倾角恢复力矩，调大 `glyphTilt` 或调小恢复系数会让字符频繁压扁而难以辨认；`erosionIrregularity`、`glyphMassVariance`、`glyphDepth` 在构建期写入字符，必须走 `setConfig` 的重建路径。
- 兼容性：整列缺口语义、蝴蝶生成、花朵生长、完成态飞行和指针互动均不改变。

## 验证方式

使用 `harness.html?check=1` 运行八项自动检查，全部通过：位移单向（最大上升 0.0000px）、60Hz 与 144Hz 一致（漂移 0.000px）、seek 与播放一致（3s 处 2.197px）、复播确定性（0px）、8 秒花园（36/36 朵开放，420 只蝴蝶）、整列缺口完整（0 列时刻分裂）、相邻字符去批次化（326 对中仅 13 对在 8ms 内）、单帧成本（1.80ms，含渲染）。再用 `harness.html?t=...` 抓取帧与 `_analysis_frames/gap-analysis-2026-09-01/reference/` 逐帧比对，并运行 `npm run build`。
