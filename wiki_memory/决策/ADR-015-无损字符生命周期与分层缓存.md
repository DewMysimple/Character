# ADR-015｜无损字符生命周期与分层缓存

## 状态

`active`

## 背景

文字坠落高峰不仅绘制实时字符，还逐帧重画整张代码卡片。3.2 秒附近一帧约有 880 次 `fillText`；到 8 秒后，透明源码仍被逐字提交，且少量已生成蝴蝶的字符会停留在变形态并继续接受 180Hz 物理。生态访花的局部分离也会对 160 只蝴蝶执行 12,720 个全量候选对。

## 决策

- 字符增加 `retired` 生命周期；按 `releaseAt` 和 ID 建立稳定释放队列，只对已释放且未完成交接的 `liveGlyphs` 做 180Hz 积分和绘制。8 秒边界保留原蝴蝶生成时刻，但立即退役尚未淡完的字符。
- 代码卡片按实际 `DPR × 舞台缩放` 建立静态底层和透明源码层。字符释放时从源码层清除对应单元，0.18 秒交接淡出单独绘制；开场显现用行级裁切，完成后只合成一次源码层。
- `AirField.sampleInto` 一次返回 X/Y 气流；花头位置在每个 60Hz 代理步按 36 朵花计算一次。花瓣使用绝对坐标绘制，避免每片花瓣反复保存和旋转上下文。
- 蝴蝶分离使用 26px 确定性均匀网格，候选仍按 ID 排序，保证与旧全量算法完全相同的力累加顺序。分离力、网格链和目标花占用量使用可复用类型数组。
- 暂停状态只在 seek、重播、参数或尺寸变化时重画一次；相同场景快照不再重复提交 React。外层 Canvas 不再和引擎重复清屏。
- 不采用 Worker、WebGL、精灵量化、降低 DPR、降低固定步长、减少对象或取消残影。实测整矩阵 `setTransform` 比局部 `save/transform/restore` 更慢，因此该候选被撤回。

## 理由

性能问题来自无效工作和全量比较，而不是视觉密度。生命周期、分层缓存和空间索引都能保持字符数量、气动物理和渲染细节，同时把成本限制到真正变化的对象。保持原有固定步累加方式也避免了批量时钟在浮点边界上改变完成态轨迹。

## 影响

- 正面影响：3.2 秒的 `fillText` 从约 880 次降至约 357 次，8 秒完成态只剩标题的一次文本绘制；空间网格将默认完成态候选从 12,720 对降至约 483 对，分离力误差为 0。
- 正面影响：8 秒时 160/160 字符全部退役，完成态不再承担字符气动开销；暂停后连续 500ms 内无 Canvas 清屏或重绘。
- 代价：卡片缓存会按渲染比例占用额外显存，并在 DPR、seek、重播或结构参数重建时失效重建。

## 验证方式

运行 `harness.html?check=1` 的十五项检查。新增检查覆盖字符退役与缓存重建、空间网格/暴力算法力一致性、默认与 220 字符的 2× DPR P95。关键帧 0.8、1.2、2.4、4.8、8.0 秒与优化前帧的 SSIM 最低为 0.999254；独立 4× CPU 降速下默认 2× DPR P95 为 4.2ms。
