# 系统架构

## 架构概览

页面采用 React 控制壳加原生 Canvas 场景引擎。React 管理播放状态、参数和面板显示；Canvas 在单个动画循环中绘制代码卡片、文字粒子、蝴蝶线稿和花朵线稿。

## 模块关系

| 模块 | 职责 | 依赖 | 入口 |
| --- | --- | --- | --- |
| `App.tsx` | 保存控制参数，连接引擎快照和面板 | React、SceneEngine | `src/main.tsx` |
| `AnimationCanvas.tsx` | 创建高 DPI Canvas、ResizeObserver、Pointer Events 和动画生命周期 | React、SceneEngine | `App.tsx` |
| `ControlPanel.tsx` | 播放、重播、时间轴、分组参数、蝴蝶轨道实验台、指针扰动实验台和恢复默认 | React | `App.tsx` |
| `scene.ts` | 场景状态机、局部传播与按列分组的坍塌调度、固定步长调度和 Canvas 绘制 | Canvas API、`glyphPhysics.ts`、`math.ts`、类型定义 | `AnimationCanvas.tsx` |
| `glyphPhysics.ts` | 字形质量度量缓存、无散度 curl noise 气流场、薄片气动积分 | Canvas measureText、`math.ts`、类型定义 | `scene.ts` |
| `math.ts` | 共享 `clamp`、`seededRandom`、缓动；独立成模块以避免循环引用 | 无 | `scene.ts`、`glyphPhysics.ts` |
| `types.ts` | Stage、PhysicsConfig、粒子和场景快照类型 | 无 | `scene.ts` |
| `harness.html` / `harness.ts` | 校准工装：确定性抓帧比对与十五项自动检查，不参与 `npm run build` | SceneEngine | 仅开发服务器 |

## 数据流

用户操作先更新 React 参数。连续数值通过 ref 同步到 Canvas 引擎，避免每帧重新渲染 React 树。Canvas 指针事件将屏幕坐标转换为 720×960 设计坐标后直接调用 `SceneEngine.setPointer`，不经过 React state。引擎根据时间、指针和参数更新对象，并以低频快照更新面板上的阶段、进度和数量。

## 场景阶段

- `intro`：0.0 至约 0.95 秒，显示代码卡片和植物轮廓。
- `falling`：从约 0.95 秒开始，默认使用约 3.4 秒的局部传播窗口；缺口先保持在中心，再向周围扩散。局部扩散模式以空间距离保持局部失稳方向，再为每个字符叠加独立的确定性释放排序扰动、初始横向速度和旋转相位，同一传播波内不会锁成三字一组或规律横排；同列坍方会把中心连续列作为完整缺口单元，中心几列在短窗口内依次打开，外侧每列按距离连续泄露，不抽样释放列内零件。
- `morphing`：字符掉落到 650 至 776 的花丛高度后才淡出并生成蝴蝶；阶段结束时间根据坍塌传播时长动态计算，避免传播尚未完成就提前切换叙事阶段。
- `bloom`：动态坍塌和变形阶段结束后至 8.0 秒，花茎、叶片和花瓣依次生长。

8 秒后时间轴保持在完成状态，`advance()` 使用实际完成的固定子步累计持续运动增量，不再从已封顶的 `time` 反推；蝴蝶、花朵风动和指针扰动因此继续由不受时间轴上限影响的 `motionTime` 驱动。

蝴蝶的飞行相位与扇翅相位分离，扇翅频率由 `PhysicsConfig.wingBeatFrequency` 控制，默认 2.8Hz。飞行使用 `approach → orbit → hover → transfer` 生态状态机：接近阶段减速到达当前花头；环绕阶段用椭圆径向回正和切向速度形成闭合轨道；悬停阶段靠近花心；转访阶段在至多六个邻近已开放花朵中按距离与拥挤度确定性选择下一目标。`homeFlowerId` 保留出生花朵和首次生长触发关系，`targetFlowerId` 表示实时访花目标。局部分离力与软边界转向防止重叠和撞边停顿。围绕半径、高度、速度、倾角、呼吸、漂移、花朵吸引、驻花时长、群体避让、飞行速度、大小和扇翅频率都可独立调节，不重建粒子、不重播；控制台“恢复默认”替换全部 React 参数，不强制重播。

花朵使用 `flowerWindStrength` 和固定随机相位产生低频自然风动；指针以花头为中心，在 `flowerPointerRadius` 内按 `pointerFalloff` 计算左右偏移，并由响应速度和回归速度控制无跳变的跟随。花朵姿态由同一条二次曲线统一计算：根部坐标固定，指针偏移同时影响枝条控制点和花头终点，花头主体绘制在枝条终点，叶片从实际枝条曲线取点，因此整株连续移动而不会出现“尸首分离”。蝴蝶在 `butterflyPointerRadius` 内使用 `butterflyPointerRepulsion` 施加二维远离力，排斥期间暂停生态状态计时；指针离开后由 `butterflyPointerReturn` 加速回到当前目标花朵，再继续访花。指针参数在完成态仍实时生效，指针状态不切换目标或改变时间轴。花枝不再由独立 `StemSeed` 额外绘制，统一由 `Flower` 对象承担，避免完成态出现无花空根。

`PhysicsConfig.collapseMode` 和 `collapseDuration` 控制文字变化形式与传播观察时长，默认是 `local-collapse` 和 3.4 秒；局部模式在空间传播顺序上叠加**加性局部抖动**（而非与整个跨度混合，后者会让中心与边缘字符几乎同时释放，导致整张卡片一起溶解而不是一个洞长大），缺口前沿半径另由角向噪声调制成不规则瓣状。`column-collapse` 使用中心 5 列作为初始缺口窗口，随后以单列为传播单位按中心到外围连续释放；同一列字符共享释放时刻和列级速度，源字符选择仍优先保留完整列，未进入动态列范围的字符保持为卡片中的静态文字。

## 字符物理

字符物理位于 `glyphPhysics.ts`，使用真实单位（px、秒、px/s²），由 `advance()` 的累加器以固定 `1/180` 秒子步驱动 `stepGlyphs`；蝴蝶、花朵和指针走独立的固定 `1/60` 秒代理累加器。`seek()` 复用两套固定子步，因此拖时间轴与播放到同一时刻结果一致，蝴蝶在 60Hz 与 144Hz 下的状态和位置也保持一致。字符按稳定释放队列进入 `liveGlyphs`，交接完成后标记 `retired` 并退出积分与渲染；8 秒边界只退役未淡完字符，不提前改变蝴蝶出生时刻。

每个字符建模为一块薄片：迎风分量与掠风分量分别乘以压差阻力与摩擦阻力系数（比值约 16:1）形成各向异性阻力，力矩取 `vn * vt` 乘积项，自发产生「兜风—减速—打滑—翻转」的往复。空气是由标量势解析求导得到的无散度 curl noise 速度场，在 24×32 粗网格上以 20Hz 预计算并双线性采样；气动力作用在相对风速上，因此相邻字符被同一个涡旋卷着走。字形质量与迎风面积由 `measureText` 的墨迹包围盒推出并按全字符集均值归一化，收尾速度按 `sqrt(mass / dragArea)` 分层。离面倾角 `tilt` 由同一股气流驱动并叠加指向正面姿态的恢复力矩，配合渲染期 `cos(tilt)` 前缩实现伪 3D 翻面；`depth` 是渲染期投影，另有沿速度反方向的运动模糊残影。

坍塌位移严格单向：允许兜风一拍内的受限瞬时上冲，但字符的 `y` 永不小于其脱落时的 `releaseY`。静态纸张背景在引擎内缓存，代码卡片拆成 DPR 感知的静态层和增量源码层，气流场按网格预计算并一次返回二维采样。花头在每个代理步按 36 朵花共享计算，蝴蝶分离使用 26px 空间网格并保持 ID 累加顺序。暂停时只在失效事件后重画一次。

## 运行与部署

开发环境使用 Vite，默认端口为 5173；若端口占用，Vite 会选择下一个可用端口。生产构建由 `tsc -b && vite build` 完成，产物位于 `dist/`，不包含参考视频。
