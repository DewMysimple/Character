# 2026-08-31｜同列坍方整列缺口修复

- 时间：2026-08-31（北京时间）
- 类型：`bug`
- 状态：`完成`
- 目标：让“同列坍方”表现为连续几列文字形成缺口后整体掉落，并按列组向周围泄露，而不是随机掉落零件。
- 日志索引：[[日志/MOC_工作日志|工作日志 MOC]]

## 问题

`column-collapse` 之前从全部代码字符中均匀抽样。即使同一列的释放时间相同，列内也可能缺少字符；独立的初始速度、抖动和垂直扰动还会让同列字符迅速分散，画面无法读取为结构性缺口。

## 实现

- 在 `src/engine/scene.ts` 中增加列级分组：中心连续 5 列为第一组，两侧每 4 列为后续传播组。
- 为列模式增加独立的源位置计划，优先收集完整列组；无法组成完整动态列组的边缘字符保留为静态卡片文字，避免出现半列断点。
- 同列字符使用一致的释放时刻、列级初始速度和列级垂直扰动，字符自身只保留旋转细节，形成连续的下落列。
- 移除列模式的释放抖动，并让坍塌时长真正参与列组传播间隔。
- `src/components/ControlPanel.tsx` 将模式显示为“同列坍方（整列缺口）”，明确该模式的视觉含义。

## 验证

- `npm run build`：通过，TypeScript 与 Vite 生产构建成功。
- `git diff --check`：通过。
- 记忆 lint：通过。
- 产物检查：通过，未跟踪 `node_modules`、`dist`、原始 MP4 或分析帧。
- 静态检查：确认列模式使用完整列组计划、同组无随机释放抖动，其他模式仍使用原有采样路径。

## 结果

同列模式现在先从中心形成贯穿多行的结构性缺口，整组文字沿原列向下掉落，再由相邻整列向外泄露；不再把中心区域渲染为随机零件散落。默认的 `local-collapse`、无回弹规则和花丛高度变形门槛保持不变。
